# Развёртывание новой версии на Windows

Исходные условия: старая версия работает по адресу http://172.16.5.6:8080/. Ниже предполагается размещение новой версии на этом же компьютере, на свободном порту 8082. Если используется другой компьютер, подставьте его IP вместо 172.16.5.6.

Старый сайт и его веб-сервер не заменяем. Итоговый адрес новой версии: http://172.16.5.6:8082/.


## Краткий план перехода

1. Проверить на целевом ПК: Windows, текущий веб-сервер, версию PostgreSQL и свободен ли порт 8082. Адрес 172.16.5.6 сохраняется только при размещении на том же ПК.
2. Отправить последние изменения нового приложения в Git и перенести код на сервер.
3. Сделать свежий бэкап рабочей БД. Для проверки восстановить отдельную копию; старый сайт оставить на порту 8080.
4. Установить и настроить новую версию по инструкции ниже: Apache, PHP, зависимости, сборка фронтенда, конфигурация БД и архив.
5. Запустить новую версию на порту 8082 как службу Windows с автозапуском.
6. Проверить вход обеих ролей, сохранение, печать и архив из реальной удалённой сессии пользователя.
7. Перед рабочим переходом остановить редактирование в старой системе, сделать финальный бэкап и перенести актуальные данные в БД новой версии. Тестовые записи в рабочую БД не переносить.
8. Дать пользователям новый адрес и ярлык. Старую версию сохранить для отката, но не разрешать параллельное редактирование двух независимых БД.
9. Настроить регулярные резервные копии БД, архива и конфигурации в отдельное место. Проверить восстановление копии.

**Откат:** если в новой версии ещё не было рабочих изменений, можно вернуть пользователей в старую. Если изменения уже появились, сначала сохранить новую БД и согласовать перенос этих изменений; простое переключение назад потеряет новые сведения.

**Готовность к запуску:** сайт открывается из удалённой сессии, запись сохраняется после повторного входа, PDF соответствует шаблону, архив загружается и скачивается, после перезагрузки ПК всё запускается автоматически.

## 1. Что установить на сервере

- Git и Node.js совместимой с проектом версии (сейчас разработка использует Node.js 22).
- PHP 8.2+ x64 Thread Safe для работы модулем Apache, Composer.
- Отдельный Apache 2.4 x64, например в C:/ApachePolytech. PHP — в C:/php-polytech. Разрядность Apache и PHP должна совпадать; необходимые Visual C++ Runtime устанавливаются по требованиям их сборок.
- PostgreSQL, если БД будет находиться на этом компьютере. Для переноса лучше использовать ту же основную версию, что у текущей БД.
- Шрифты Times New Roman: times.ttf, timesi.ttf, timesbd.ttf, timesbi.ttf в C:/Windows/Fonts.

Если имеющийся веб-сервер уже подходит, можно добавить к нему отдельный сайт. Но не обновляйте PHP старого приложения без проверки его совместимости. Изолированная установка новой версии позволяет не затрагивать старую.

## 2. Перенести приложение

Перед клонированием нужно отправить актуальные изменения в репозиторий: последние локальные правки могут ещё отсутствовать на GitHub.

В PowerShell, при условии что git, node/npm, php и composer доступны через PATH:

```powershell
git clone https://github.com/egortriston/new_poly_gek.git C:/Sites/polytech-next
Set-Location C:/Sites/polytech-next
npm ci
npm run build
composer install --working-dir=backend --no-dev --optimize-autoloader
composer check-platform-reqs --working-dir=backend
```

Composer должен использовать именно новый PHP. Проверить путь можно командой `Get-Command php`. Для Apache используются файлы сборки `dist`, а не сервер Vite. Постоянно запускать Node.js не требуется.

## 3. База данных и личные настройки

Приложение ожидает существующую структуру БД `legacy_poly`. Миграции и создание таблиц не запускать.

Есть два варианта:

- Подключить приложение к нужной уже работающей БД, указав её адрес и реквизиты. Тогда изменения из обоих приложений попадут в одну БД.
- Для проверки новой версии восстановить свежий бэкап в отдельную БД. Это удобнее до окончательного перехода: действия в новой версии не затронут пользователей старой.

Не восстанавливайте бэкап поверх рабочей БД. Для отдельной копии, если утилиты PostgreSQL доступны в PATH:

```powershell
createdb -h 127.0.0.1 -U postgres -W legacy_poly_new
pg_restore -h 127.0.0.1 -U postgres -W --no-owner --no-privileges --exit-on-error -d legacy_poly_new C:/Transfer/current.backup
```

Команды рассчитаны на архивный формат pg_dump, включая custom .backup. Для обычного SQL-дампа используется psql. Бэкап должен содержать актуальные данные; старый сентябрьский бэкап не содержит более поздних изменений.

Скопировать `backend/config.example.php` в `backend/config.local.php` и заполнить:

```php
<?php
return [
    'db' => [
        'host' => '127.0.0.1',
        'port' => '5432',
        'dbname' => 'legacy_poly_new', // либо имя нужной существующей БД
        'user' => 'postgres',
        'password' => 'УКАЖИТЕ_ПАРОЛЬ_БД',
    ],
    'roles' => ['admin' => 'admin', 'rop' => 'rop'],
    'secure_cookie' => false, // для указанного HTTP; для HTTPS — true
    'idle_seconds' => 1800,
    'absolute_seconds' => 28800,
    'archive_root' => dirname(__DIR__).'/storage/archive',
    'archive_max_file_bytes' => 52428800,
    'print_font_dir' => 'C:/Windows/Fonts',
];
```

Пароли входа в сайт хранятся в таблице user_list, а не в roles. Пароль подключения PostgreSQL — отдельный реквизит.

Если нужно перенести уже загруженные файлы архива, отдельно скопировать `storage/archive` с сохранением всей структуры. Настройки из `config.local.php`, содержимое `storage` и `backend/var` в Git не попадают. Для переноса настроек нумерации ГЭК отдельно сохранить `backend/var/gek-numbering.json`, если он существует. Временные PDF, кэш и сессии переносить не нужно.

## 4. Настроить PHP

Создать C:/php-polytech/php.ini на основе php.ini-production. Включить расширения:

```ini
extension_dir = "C:/php-polytech/ext"
extension=pgsql
extension=mbstring
extension=gd
extension=zip
upload_max_filesize=50M
post_max_size=64M
memory_limit=512M
max_execution_time=120
display_errors=Off
log_errors=On
```

Проверка `composer check-platform-reqs` должна проходить без ошибок. PHP-модулю Apache могут понадобиться библиотеки из папки PHP в системном PATH, в частности для PostgreSQL. После изменения PATH перезапустите службу.

## 5. Настроить отдельный Apache

В C:/ApachePolytech/conf/httpd.conf используйте стандартную конфигурацию дистрибутива. Исправьте существующие ServerRoot, Listen, ServerName, DocumentRoot и основной блок Directory; добавьте настройку PHP и Alias ниже. Не дублируйте Listen и загрузку одного модуля. Стандартные модули alias, dir и mime должны быть включены.

```apache
ServerRoot "C:/ApachePolytech"
Listen 8082
ServerName 172.16.5.6:8082

LoadModule php_module "C:/php-polytech/php8apache2_4.dll"
PHPIniDir "C:/php-polytech"
AddHandler application/x-httpd-php .php

DocumentRoot "C:/Sites/polytech-next/dist"
<Directory "C:/Sites/polytech-next/dist">
    Options -Indexes
    AllowOverride None
    Require all granted
    DirectoryIndex index.html
    FallbackResource /index.html
</Directory>

Alias "/api/" "C:/Sites/polytech-next/backend/public/"
<Directory "C:/Sites/polytech-next/backend/public">
    Options -Indexes
    AllowOverride None
    Require all granted
    DirectoryIndex index.php
    FallbackResource /api/index.php
</Directory>
```

Каталог всего проекта нельзя назначать DocumentRoot: наружу выдаются только dist и backend/public. К архиву приложение обращается через API.

У аккаунта службы Apache должны быть права чтения проекта и шрифтов, записи в `backend/var` и `storage/archive`. Не выдавайте пользователям сайта прямой доступ к этим папкам.

В PowerShell от администратора:

```powershell
& C:/ApachePolytech/bin/httpd.exe -t
& C:/ApachePolytech/bin/httpd.exe -k install -n PolytechNew
Set-Service -Name PolytechNew -StartupType Automatic
Start-Service PolytechNew
```

Первый шаг должен завершиться `Syntax OK`. Если служба уже установлена, повторять установку не нужно. PostgreSQL также должен запускаться автоматически.

## 6. Доступ пользователей

- Через удалённый рабочий стол именно этого сервера: открыть браузер внутри удалённой сессии и перейти на http://127.0.0.1:8082/.
- Через удалённый рабочий стол другого компьютера в сети: открыть http://172.16.5.6:8082/.
- Со своего компьютера при наличии доступа к этой сети: тот же адрес http://172.16.5.6:8082/.

Для сетевого доступа разрешите входящий TCP-порт 8082 в брандмауэре сервера только для нужной локальной сети или конкретных адресов. Подсеть уточняется у администратора сети — из одного адреса 172.16.5.6 её маску определить нельзя. Если доступ нужен только через RDP на сам сервер, сетевой доступ к порту сайта не обязателен.

Открывать PostgreSQL пользователям не требуется. Запускать отдельный экземпляр сайта для каждой удалённой сессии тоже не нужно: служба Apache обслуживает всех. Число одновременных RDP-сессий зависит от установленной Windows и её настройки, отдельно от сайта.

## 7. Проверка перед использованием

1. На сервере открыть http://127.0.0.1:8082/api/v1/health — должен вернуться JSON со status: ok.
2. Открыть сайт, войти под admin и РОП.
3. Проверить чтение реальных данных, создание и удаление тестовой записи в тестовой БД.
4. Обновить страницу /oop/formation напрямую — она должна открываться без 404.
5. Открыть PDF ГЭК и ООП, проверить шрифты, скачать документ.
6. Загрузить тестовый файл в архив и скачать обратно.
7. Перезагрузить сервер и повторить вход: сайт должен работать без открытого терминала разработчика.
8. Проверить доступ из той удалённой сессии, которой реально будут пользоваться сотрудники.

Если health работает, но вход или таблицы нет — проверить config.local.php и подключение БД. Если PDF не формируется — расширения PHP, шрифты и права записи backend/var. Если работает с сервера, но не из сети — адрес, маршрут и правило брандмауэра.

## 8. Обновление и резервные копии

Перед обновлением сохранить бэкап БД, архив файлов и личную конфигурацию. При размещении новой версии рядом со старой не переключайте пользователей на общую БД до проверки.

Для обновления кода: `git pull`, `npm ci`, `npm run build`, `composer install --working-dir=backend --no-dev --optimize-autoloader`, затем перезапуск PolytechNew. Делать в согласованное время без активной работы пользователей. Не удалять storage и config.local.php.

Эта конфигурация использует HTTP в существующей внутренней сети. При настройке HTTPS следует включить secure_cookie=true и использовать один постоянный адрес сайта.

- Установка службы Apache: https://httpd.apache.org/docs/2.4/programs/httpd.html
- PostgreSQL pg_restore: https://www.postgresql.org/docs/current/app-pgrestore.html

Инструкция подготовлена по текущему коду. Конфигурация Apache на целевом сервере пока не проверялась; его ОС, занятые порты и установленный веб-сервер нужно сверить перед установкой.
