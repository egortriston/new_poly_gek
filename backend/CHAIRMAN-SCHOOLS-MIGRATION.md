# Связь председателей с высшими школами

Новая таблица `sec_chair_school(id_predsedatel_sc, id_school)` объединяет связи из `sec_helper` и `sec_complex_sc`. Первичный ключ запрещает повтор пары; внешние ключи защищают ссылки на карточку и школу. Тип председателя остаётся в `sec_predsedatel_s.complex`. У обычного председателя приложение допускает одну школу, у комплексного — несколько.

Миграция переносит только однозначно сопоставленные связи. Строки без карточки, с несколькими возможными карточками или без действующей школы остаются в исходных таблицах. В выводе `unresolved_regular_ids` и `unresolved_complex_ids` указаны их старые ID. Скрипт не создаёт карточки за пользователя и не удаляет старые таблицы.

Новый код читает общую таблицу. При сохранении и снятии назначения он временно обновляет также старые таблицы, чтобы сохранилась возможность вернуть предыдущую версию приложения. Это переходный этап, а не окончательное удаление старой структуры.

## На Windows-сервере

Из административной PowerShell, в согласованное окно без пользователей:

```powershell
Set-Location 'C:\Program Files (x86)\Site'
Stop-Service PEMHTTPD
git pull --ff-only
php backend/bin/migrate-chairman-schools.php --check
php backend/bin/migrate-chairman-schools.php --simulate
php backend/bin/migrate-chairman-schools.php --apply
Start-Service PEMHTTPD
```

Каждый запуск без `--database` обрабатывает все БД со статусом `ready` из приватного `backend/var/databases.json`. Если хотя бы одна из них недоступна, остановись и исправь список/подключение до запуска `--apply`: интерфейс позволяет выбирать все зарегистрированные БД. Для диагностики отдельной базы добавь `--database=имя_из_реестра`.

`--check` не меняет БД. `--simulate` создаёт и заполняет таблицу внутри транзакции, затем откатывает её. `--apply` сначала делает дамп **каждой** выбранной БД в `backend/var/db-backups/chairman-schools/`, затем применяет миграцию в отдельных транзакциях. Каталог `backend/var` исключён из Git; дампы содержат рабочие данные и должны оставаться закрытыми для посторонних. При ошибке `--apply` не запускай веб-сервер до устранения причины и повторного успешного запуска: уже обработанные БД сохранят изменения, а повторная миграция не создаст дубли.

После запуска проверь карточку обычного и комплексного председателя, фильтр школы, выбор председателя в ГЭК и печать списка председателей по школе. Если нужен откат, останови веб-сервер и верни предыдущий коммит приложения. Пока действует параллельная запись в старые таблицы, связи после миграции остаются доступными старому коду. Дампы позволяют восстановить состояние БД целиком при более серьёзной ошибке; восстановление не выполняется автоматически.
